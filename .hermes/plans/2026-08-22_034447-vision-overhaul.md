# omnigate vision overhaul

> **For Hermes:** Implement phase-by-phase. Phase 0 first. Do not collide with Omarchy’s existing `omarchy-migrate` (that is their *update* repair runner). Do not mention AI/LLM/Needle in any user-facing string.

**Goal:** Omnigate is the on-ramp. It is only allowed to occupy **five minutes** of their life, and those five minutes must **feel like fifteen seconds**. Then Omarchy — for people who love their computers or want to — takes over. Do not sand Omarchy down. Do make the Windows-side wizard fast and obvious.

**Architecture:** Two halves, one journey. **Source half** (Windows/macOS/Linux they already have): a single plain-language wizard. **Destination half** (after Omarchy exists): first-run hook + menu leaf that speak Omarchy’s language (`omarchy` CLI, gum, notices, `$OMARCHY_PATH`). Keep-disk. ISO still owns the install. We never invent a second installer.

**Tech stack:** Source = Python 3.9+ stdlib + `omnigate.ps1` / `.sh` (later one-click pack). Destination = bash that matches `basecamp/omarchy` `AGENTS.md` (shebang `#!/bin/bash`, `omarchy-*` helpers, gum, notifications). Optional Needle sidecar, invisible.

---

## 1. Who this is for (lock)

Two products. Two audiences. Do not mix them.

| | **Omnigate** (this repo) | **Omarchy** (basecamp) |
|--|--------------------------|------------------------|
| For | People *leaving* a crusty Windows/Mac/Linux box | People who **love their computers, or want to** |
| Job | Get them there with their stuff. Keep the old disk. | Be a beautiful, opinionated, AI-first Arch desktop |
| Voice | Plain. “Your Windows stays.” Three piles. | Their voice: Super+Space, gum, menu, notices, `omarchy` |
| Do not | Teach SSH, flakes, agents, or JSON | Dumb it down into “Windows but green” |

Omnigate’s **source** buyer (unchanged):

| Persona | Machine | Fear |
|---------|---------|------|
| Gamer | Old Win10/11, Steam, maybe FSX | Losing the library / saves |
| Office user | Crunchy laptop, Word/Outlook/printers | Wipe / “I’m not a computer person” |

They may not be developers. They may still *want* to love the machine — that is why Omarchy is the destination. After first boot, stop babysitting. Hand them Omarchy’s coming-from-Windows chapter, Super+K, the menu. If they later pick a default agent, that is Omarchy’s invite, not ours.

Business here = a person who uses a PC at work, not an MSP. One wizard for gamer and office. Hidden `--yes` / `--dry-run` only.

They should not need python.org, `plan.json`, or SSH to *start*. After they land, they are Omarchy users — treat them that way.

## 3. What Omarchy conventions we must match

Read before any destination-side file: `~/Projects/omarchy/AGENTS.md`.

### Language and docs
- Three trees: `agents/skills/` (how to work), `docs/` (shape), `manual/` (humans). User-facing text never leaks internals.
- Markdown: full lines, no 80-col wrap; break at headings/lists only.
- Atomic commits. Succinct messages.

### Commands (destination)
- All commands start with `omarchy-`. Groups in `bin/omarchy` `GROUP_DESCRIPTIONS`.
- Metadata comments: `# omarchy:summary=`, `# omarchy:args=`, `# omarchy:hidden=true`.
- Prefer `omarchy <group> <action>` in docs, not raw binaries.
- Helpers: `omarchy-cmd-present`, `omarchy-pkg-add`, `omarchy-notification-send`. Never raw `notify-send`.
- Privilege: `sudo` when a terminal can take a password; `pkexec` only when there is no TTY.
- `$OMARCHY_PATH` is given. Do not invent fallbacks from `$HOME`.
- Shebang `#!/bin/bash` (never `#!/usr/bin/env bash`).
- `[[ ]]` / `(( ))`. Quote paths with spaces.

### UI they already taught users
- **gum** `choose` / `input` / `filter` is the ISO vocabulary (Esc / Ctrl+C abort). Our destination wizard should be gum, not a new TUI dialect.
- Osaka Jade / current theme via `themes/*/colors.toml`. Do not hardcode a second palette on the destination; follow current theme if possible, else Osaka Jade (Omarchy default).
- Menu: `default/omarchy/omarchy-menu.jsonc`. New leaf: **Setup → Import from your old PC** (no aliases).
- Notices: first-run hooks under `install/user/first-run/`. Silent until they click.
- Coming-from-Windows is a **translation table** (Start menu → Super+Space). Our post-import recap should speak that way: “Chrome is Chromium. Word is LibreOffice (or Collabora). Your games are still on D:.”

### Install ownership
- **The ISO owns installation.** `install/` leaves are sourced; no shebang; no `exit` unless aborting setup.
- Dual-boot is already documented (`manual/` Dual Boot Install). That **is** our keep-disk default. Do not invent a third partitioner.
- Unattended installs exist for labs. Not the primary buyer.
- `omarchy-refresh-config` copies defaults with backup. Restore must **merge**, never clobber Omarchy-owned files.
- Never write `/usr/share/omarchy/`. User state lives in `~/.config/`.

### Migrations (theirs, not ours)
- `migrations/<unix>.sh` = one-time repairs on `omarchy update` / login notify.
- If omnigate must fix state on an *already installed* Omarchy, ship an Omarchy-format migration (echo first line, idempotent, 0644, no shebang).
- Incoming-from-Windows is **not** an Omarchy migration. It is a **setup** command.

**Proposed destination names (pick these, do not bikeshed later):**

| Role | Command | Why |
|------|---------|-----|
| Router | `omarchy setup import` | `setup-` is their wizard prefix |
| Binary | `omarchy-setup-import` | filename matches group |
| Menu | Setup → Import from your old PC | human |
| Source (Windows) | `Omnigate` / `omnigate.ps1` | foreign OS; Omarchy CLI does not exist yet |
| Forbidden | `omarchy-migrate`, `omarchy migrate` | already taken |

## 4. The journey (same for gamer and office user)

Plain words. Buttons and lists. No JSON on screen.

| Beat | Screen says | They do | Rollback |
|------|-------------|---------|----------|
| 0 Look | “We found your programs and files. Your old Windows stays.” | Next | Close |
| 1 Choose | Three piles: **Coming with you** / **Already in Omarchy** / **Needs a decision** | Tick. Never type a package name | Close |
| 2 Try (if we can) | “Try Omarchy with your files. Nothing is permanent.” | Use it | Quit = throw away |
| 3 Install | “Install Omarchy next to Windows. You can still boot Windows.” | Confirm once | Boot Windows |
| 4 Finish | On first Omarchy login: “Bring in your files?” gum table | Yes | Old disk still there |
| 5 Live | Translation recap + Super+Space | Live | Boot Windows |

Needle never appears. Leftovers are folded: “system leftovers (14)” not 14 raw names.

**Gamer-specific lines (honest):**
- Steam games: “They stay on your old drive. Steam on Omarchy can play them. We do not copy 600 GB.”
- Anti-cheat (Valorant): “This one only works on Windows. Boot Windows to play it.”
- FSX addons: “These stay on Windows.”

**Office-specific lines:**
- Word/Excel: opinionated default + choice (Collabora / LibreOffice). No jargon.
- Outlook: honest — mail in browser or Thunderbird; PST is a decision, not a silent skip.
- Printers: “We kept the name. You may need to click the printer again.”
- PDFs: Omarchy already has a PDF chapter — defer.

## 5. Source half (crusty Windows) — must feel dumb-simple

Omarchy conventions **do not exist** on Windows. Do not fake `omarchy-` there.

**Ideal:** one folder they download, double-click `omnigate.ps1` or later `Omnigate.exe`.

**Today’s gap:** we require Python + git. For this buyer that is a wall.

Phase order for source UX:
1. Keep scripts, but `omnigate.ps1` **offers** to install Python via `winget` if missing (one prompt, their words: “We need a small helper. OK?”).
2. Later: PyInstaller/flet pack one `.exe` that *is* the wizard. Still calls the same Python brain.
3. Never ask them to open a terminal first if we can avoid it. PowerShell `-ExecutionPolicy Bypass -File` in a `.bat` next to the script.

Copy: “Your Windows is not erased.” Every screen.

No SSH. No `--target`. No capability essay. If we cannot preview on Windows, skip beat 2 and say: “You’ll try it after Omarchy is installed. Windows will still be there.”

Hardware snapshot (PCI/GPU IDs) runs silently. They never see “sysfs.”

## 6. Destination half — look like Omarchy

After the ISO/dual-boot:

1. `install/user/first-run/import-old-pc.hook`  
   If `~/omnigate-package.zip` or a known USB/old-disk path exists, notice:  
   “Finish moving your files” → `omarchy menu summon setup.import`  
   Same pattern as `setup-agent.hook` (invite once, `omarchy-done ensure`).

2. `bin/omarchy-setup-import`  
   gum choose/confirm table. Calls Python import **or** a thin bash wrapper around `migrate.py import`.  
   `# omarchy:group=setup` `# omarchy:summary=Import files from your old Windows or Mac`

3. Menu leaf in `omarchy-menu.jsonc` under Setup. No aliases.

4. Recap uses **coming-from-Windows** voice, then `omarchy-notification-send`.

5. Theme/bar/agent: **do not touch**. `omarchy-refresh-config` already owns defaults. We merge user configs that Omarchy does not own (git, ssh pubkeys, browser bookmarks).

6. If we must repair later, add `migrations/<ts>.sh` in *their* format — not a second migrator.

**Do not vendor Omarchy.** If this ships as a third-party tool, destination files live in *our* repo as a drop-in (`contrib/omarchy/`) until/unless upstream wants them. Follow their style anyway so a PR would not be embarrassing.

## 7. What is wrong today (vs this design)

- Four developer front doors. No Windows double-click story.
- `anywhere.py` talks SSH/fleet/JSON — wrong buyer.
- Skill still says NixOS flake swaps.
- Destination does not use gum / menu / first-run / `omarchy-notification-send`.
- Name risk: we keep saying “migrate” next to their `omarchy-migrate`.
- `app.py` says Flutter and read-only.
- Generator thinks Home Manager is the landing identity. Landing is Omarchy packages + `~/.config`. HM is gaps only (Hermes, gitlawb, etc.).
- No Steam/office plain-language verdicts in the wizard.
- Python+git wall for the actual user.

## 8. Phased plan

### Phase 0 — Honesty

**Objective:** Docs and skills match this buyer and Omarchy’s AGENTS.md.

**Files:**
- Modify: omnigate-development `SKILL.md` — delete flake/`nixos-rebuild` block. State: destination Arch Omarchy; buyer = gamer/office Windows; never take `omarchy-migrate`; defer agents/themes.
- Modify: `docs/VISION.md` — buyer, dual-boot as keep-disk, destination command names, AI stays Omarchy’s.
- Create: `docs/AUDIENCE.md` — personas + forbidden words (LLM, Needle, flake, SSH as the happy path).
- Create: `docs/OMARCHY_CONVENTIONS.md` — short digest of their AGENTS.md as it applies to us (names, gum, menu, hooks, privilege).
- Modify: `README.md` — lead with Windows/gamer/office, not `python3 anywhere.py --target`.

**Acceptance:** no `nixos-rebuild` in the omnigate skill. README does not lead with SSH.

---

### Phase 1 — One wizard, human words

**Objective:** Source UI is one stepper. No JSON. No AI words.

**Files:**
- Create: `journey.py` — beats Look / Choose / Try / Install / Finish / Live.
- Create: `tests/test_journey.py` — fleet/SSH is not required; help text has no LLM/Needle.
- Modify: `tui.py` + `configurator.py` — this *is* the source wizard. gum-like choose already exists; make lists the three piles.
- Modify: `installer.py` — destination Finish beat only.
- Modify: `omnigate.ps1` — if no Python, offer `winget install Python.Python.3.12`; launch wizard, not `--help`.
- Modify: `app.py` — optional full-screen skin of the **same** beats; detect OS; hide dead Try tiers; stop “read-only.”

**Copy tests:** user-visible strings file or grep fixture. Forbidden: LLM, Needle, chatbot, flake, kexec, disko.

---

### Phase 2 — Honest piles (gamer + office)

**Objective:** Choose screen tells the truth without packages.

**Files:**
- `verbs.py` + `oracle.py` plan.md renderer — human labels:
  - skip → “Stays on your old drive (games)”
  - defer → “Omarchy already has this”
  - containerize → “Runs in a Windows box if you need it” (later)
  - no_linux → “Windows only — boot Windows”
  - noise → folded, not shown
  - real_unknown → “Needs a decision”
- `mappings/apps.json` — office + Steam already partly there; add Outlook/Teams/OneDrive honest rows; defer Omarchy agent launchers **silently** (no “AI” in reason string).
- `tests/test_verbs.py` — Cyberpunk = skip; Carenado = no_linux; Word = mapped with alternatives; org.freedesktop = noise.

---

### Phase 3 — Keep-disk install = their dual-boot

**Objective:** We do not write a new installer. We walk them to Omarchy’s ISO + dual-boot chapter.

**Files:**
- `anywhere.py` retitled in UI as “Install next to Windows.” Implementation: write a **checklist** (download ISO, boot USB, pick the empty/second disk, do not format the Windows partition) and optionally open `https://omarchy.org/manual/dual-boot-install/`.
- Keep `--wipe --i-understand-wipe` as a hidden developer escape. Not in the wizard.
- Export zip + hardware snapshot + “put this zip on a USB named OMNIGATE.”

**Acceptance:** wizard never runs `sgdisk --zap`. Probe still lists Windows partitions as KEEP.

---

### Phase 4 — Destination: `omarchy setup import`

**Objective:** First login on Omarchy feels native.

**Files (in our repo `contrib/omarchy/` until upstream):**
- `bin/omarchy-setup-import` — `#!/bin/bash`, metadata comments, gum, calls import.
- `install/user/first-run/import-old-pc.hook` — invite once.
- Menu snippet for `omarchy-menu.jsonc`.
- Recap via `omarchy-notification-send`.
- Tests: `test/shell.d/setup-import-test.sh` style if we run in an Omarchy guest; otherwise Python tests that the hook is idempotent / invite-once.

**Privilege:** sudo only when mounting the old NTFS/home. pkexec if launched from the menu with no terminal.

---

### Phase 5 — Try (optional) + one live restore

- Windows: skip Try if no WSL/Docker. Say so in one sentence.
- Linux/dev: writable overlay Peek, commit/discard.
- Live import on the existing Omarchy guest with `--yes`. Prove backup + rollback.

### Phase 6 — Later (do not start)

- WinPodX containerize for Adobe.

- MicroVM Feel.
- Cluster/k3s (not this buyer).
