# omnigate build-out plan

> **For Hermes:** Implement phase-by-phase. Phase 0 first. Do not start Phase 2 until Phase 1 is honest. Use `subagent-driven-development` for the build tasks.

**Goal:** Ship the on-ramp a 78-year-old Windows 11 user and a 56-year-old macOS user will actually finish. One Flet window. Three piles. Keep the old disk. Five minutes that feel like fifteen seconds. Then Omarchy.

**Architecture:** One Flet `app.py` wizard (the only UI). One `journey.py` beat machine behind it. Material 3 responsive layout (from the skills we just installed). On Omarchy: a `contrib/omarchy/` setup-import hook + menu leaf that follows their `AGENTS.md`.

**UX principle — ladder skipping:** The fast path is the default. Auto-advance through beats where the answer is safe and obvious. Make every rung visible so the user trusts the skip. Stop only when a real choice exists (the unknown pile). Never force a click-through for its own sake.

**Tech stack:**
- Wizard: **Flet 0.86.5** (already in `.venv-flutter`, Python 3.13) → `flet pack` → `Omnigate.exe` / `Omnigate.app`
- Material Design 3 via `ColorScheme.fromSeed(Colors.green)` with Osaka Jade tokens
- Responsive: `LayoutBuilder` + breakpoints (mobile / tablet / desktop)
- Destination: bash, gum, `omarchy-menu.jsonc`, first-run hook, `$OMARCHY_PATH`
- Backend: existing `scanner/`, `mapper/`, `verbs.py`, `hardware.py`, `oracle.py`, `migrate.py`

### The journey (same for Win / Mac / Linux)

Ladder skipping: the fast path is the default. Auto-advance through beats where the answer is safe. Stop only for real decisions.

| Beat | Screen | Default action | Stop? |
|------|--------|----------------|-------|
| 0 Look | Counts + three piles + "old disk stays" | Auto-advance after 2s once scan finishes | No (watch it happen) |
| 1 Choose | Three piles. Honest labels. | Pre-selected defaults (keep everything that maps, skip nothing) | Only if they tap "Needs a decision" |
| 2 Keep | "Install Omarchy next to Windows" + ISO link | One click → dual-boot walk | Yes (confirm once) |
| 3 Land | "Put zip on a USB" + done | Finish | No |

Scan runs the instant the window opens. No "click to scan" button. They see the work happening — that is the trust.

If everything maps (no unknowns), the whole wizard is: see counts → confirm keep → put zip on USB. Three interactions. Fifteen seconds.

### Destination: `contrib/omarchy/`

On first Omarchy login: a notice (like "Set your default agent") → `omarchy menu summon setup.import` → gum wizard → bring in the zip.

| File | Purpose |
|------|---------|
| `bin/omarchy-setup-import` | `# omarchy:group=setup`, gum, calls `migrate.py import` |
| `install/user/first-run/import-old-pc.hook` | invite once |
| Menu snippet | Setup → Import from your old PC |
| Recap | `omarchy-notification-send` |

Name is `omarchy-setup-import`. **Never** `omarchy-migrate` (that is their update repair command).

## 2. Material 3 + responsive layout (from installed skills)

Apply the three skills we just installed:

| Skill | How we use it |
|-------|---------------|
| **material-3** | `ColorScheme.fromSeed(seedColor: Color(0xFF549e6a))`. Osaka Jade tokens as `--md-sys-*`. Tonal surfaces, spring motion. Contrast ≥ 4.5:1. |
| **flutter-build-responsive-layout** | `LayoutBuilder` + breakpoints. Compact (<600dp): single column. Medium (600–840): side-by-side piles. Expanded (>840): constrained max-width, centered. Never orientation-locked. |
| **flutter-apply-architecture-best-practices** | MVVM. ViewModels own beat state. Views are lean. Flet maps this naturally. |

Flet uses Material under the hood. We set `theme=ft.Theme(color_scheme_seed=ft.Colors.GREEN)` and override tokens with Osaka Jade hex.

### Phase 1 — Journey machine + ladder skipping

**Files:**
- Create: `journey.py`
  - `BEATS = (look, choose, keep, land)` enum
  - `detect_platform() -> {os, is_windows, is_macos, is_linux}`
  - `scan_counts() -> {coming, already, decide, unknown}` (shallow, <1s)
  - `auto_advance(beat) -> bool` — returns True when the beat can skip itself (look always; choose only if unknown is empty; land always)
  - `make_package(out)` (wraps existing export)
  - `run_beat(beat)` dispatcher
- Create: `tests/test_journey.py`
- Modify: `bootstrap.py` — add `wizard` subcommand that calls `journey.run_beat`

**Tests (write first):**
```python
def test_detect_platform_returns_os():
    p = detect_platform()
    assert p.os in ("windows", "macos", "linux")

def test_scan_counts_never_runs_du():
    # mock os.scandir; assert depth capped at 1, entry count capped
    ...

def test_beat_order_is_look_choose_keep_land():
    assert BEATS == (BEAT_LOOK, BEAT_CHOOSE, BEAT_KEEP, BEAT_LAND)

def test_look_beat_auto_advances():
    assert auto_advance(BEAT_LOOK) is True

def test_choose_beat_stops_when_unknowns_exist():
    # if unknown pile non-empty, do not auto-advance
    assert auto_advance(BEAT_CHOOSE, unknown_count=3) is False

def test_choose_beat_advances_when_all_mapped():
    assert auto_advance(BEAT_CHOOSE, unknown_count=0) is True
```

## 5. Principles

- **YAGNI:** No microVM, no full-VM tier, no State Alchemy, no Coffin, no Cross-OS Delta Feed in this build. Phase 2+ are out of scope.
- **TDD:** Every task writes the failing test first.
- **DRY:** `journey.py` is the single source of truth for beats. `app.py` only renders.
- **Five minutes:** If a screen does not serve the clock, cut it.
- **Never `omarchy-migrate`:** That command is taken.

## 7. Risks

| Risk | Mitigation |
|------|------------|
| Flet unavailable on Windows pack target | Test `flet pack` early (Phase 9 spike in Phase 2) |
| Needle invents packages | Schema has no `pkg` field; fail-open |
| Omarchy clobber | Defer rule; merge-restore; never `/usr/share/omarchy` |
| Name collision | `omarchy-setup-import`, never `omarchy-migrate` |
| AI jargon leak | Forbidden-word test in Phase 6 |
| Two agents edit `app.py` | Phase 2–4 are one agent |
