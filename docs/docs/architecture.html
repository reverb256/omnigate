01The three layers

Migrating an OS is not a file copy. It is a mount, a delta, and a manifest.

Layer 1

Union mount

The old disk is mounted read-only as an overlayfs lower layer under the new OS. Data appears at its new path with zero copy.

systemd gpt-auto-generator + Discoverable Partitions Spec
Layer 2

Differential sync

Copy only what changed; skip what's re-downloadable. Reflink-first (btrfs/XFS CoW) means near-instant, no duplicate space.

blake3 parallel hash + Vulkan GPU backend in the Rust core
Layer 3

Declarative manifest

The whole machine described as a rebuildable manifest. Migration = git diff old-manifest omarchy-manifest.

defer rule fires automatically against the Omarchy reference

02The two-sided shape

                                       union mount (zero copy)

Export runs on the source machine — all three OSes. Import runs on the fresh Omarchy box and is additive: it defers to Omarchy on everything Omarchy already provides.

03The skip ladder

The fastest transfer is the one you don't do.

1 · MOUNTData stays where it is; the new OS sees it through overlayfs.
2 · REFLINKCopy-on-write — near-instant, zero extra space.
3 · SKIPSteam games, caches, anything re-downloadable never moves.
4 · DEDUPChunked sync — only novel bytes cross the wire.
5 · HASHblake3 on deltas (12× sha256), trust the reflink.

omnigate moves 20 GB, not 1 TB. The unavoidable transfer gets a Rust core: parallel blake3 hashing, reflink-first copies, and a portable Vulkan-compute GPU backend (CUDA/ROCm/SYCL feature-gated).

04The governing rule

Defer to OmarchyIf Omarchy provides it, don't duplicate it.
Never guessUnknown apps get flagged for review, never auto-mapped.
Zero-copy firstMount before you copy. Copy only what changed.
Rollback alwaysThe old system stays bootable until you say otherwise.
