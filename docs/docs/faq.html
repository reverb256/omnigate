/FAQ

Is it safe?

The old system stays bootable until you say otherwise. The default is rollback-always: mount is read-only, sync is dry-run until you review the plan, and nothing destructive happens without an explicit confirm.

Does it move my Steam games?

Depends what "move" means. The union mount makes your existing Steam library visible to Omarchy with zero copy — games launch immediately, no reinstall. The skip ladder then decides what actually needs to transfer: anything re-downloadable stays put.

What about Windows apps with no Linux equivalent?

Three tiers. SKIP — Steam games stay on NTFS, Proton mounts them. DEFER — apps with an Omarchy equivalent map to it. CONTAINERIZE — MS/Adobe suites and kernel anti-cheat games run in a Windows container (dockur + Podman + FreeRDP RemoteApp), surfaced as native Linux windows. Migration = install the container, don't port the app.

Is there a hard wall?

One: kernel-level anti-cheat (Valorant/Vanguard) cannot run on Linux. omnigate will tell you this plainly instead of pretending otherwise.

Does it need an LLM at runtime?

No. The runtime is deterministic — zero LLM calls. AI is used to build it (agents write the code, curate the mapping database, tune the algorithms), never to run it.

What does "defer to Omarchy" mean?

If Omarchy has a supported way to provide or configure something, omnigate defers to it — it doesn't duplicate it. Unknown apps get flagged for review, never auto-mapped. The tool is additive by design; it never fights Omarchy.

Is it really cross-platform?

Yes. The export side runs on Linux, macOS, and Windows with three stdlib launchers (omnigate.sh, omnigate.ps1, bootstrap.py). Only the mount layer is Linux-target (overlayfs + root).

How fast is it really?

The skip ladder is the honest answer: mount > reflink > skip > dedup > hash-delta. omnigate moves 20 GB, not 1 TB. The unavoidable transfer gets parallel blake3 hashing (12× sha256) and a portable Vulkan-compute GPU backend.
